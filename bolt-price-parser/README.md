# Bolt Price Parser

Веб-приложение, которое показывает **актуальную стоимость поездки Bolt по всем тарифам**
для заданных адресов начала и конца. Данные берутся в реальном времени из веб‑портала
**Bolt Business / Ride Booker** (`business.bolt.eu`) — единственной доступной по логину/паролю
поверхности Bolt, где видны цены по категориям.

> Город по умолчанию — **Рига (Rīga)**. Меняется в `.env`.

---

## ⚠️ Важно прочитать

- **У Bolt нет публичного API** для расчёта стоимости поездки. Инструмент автоматизирует
  веб‑портал через headless‑браузер (Playwright). Это **противоречит условиям использования
  Bolt** и может привести к капче, запросу 2FA или блокировке аккаунта. Используйте на свой
  риск и только со своим аккаунтом.
- **Секреты не хранятся в коде.** Логин/пароль задаются только в `.env` (в `.gitignore`).
  Если вы где‑то присылали пароль в открытом виде — **смените его**.
- Вёрстка портала может меняться — тогда нужно поправить селекторы/логику в
  `src/boltBusiness.js`. Для диагностики есть режим `DEBUG_CAPTURE=1` (скриншот + дамп JSON).

## Два источника цен

Переключается настройкой `PROVIDER` в `.env`. По умолчанию `auto`: если вход через
приложение уже сделан (`npm run login:mobile`), берётся мобильный источник, иначе —
веб‑портал. Явное значение `web` или `mobile` всегда перекрывает автовыбор.

| | `PROVIDER=web` | `PROVIDER=mobile` |
| --- | --- | --- |
| Что автоматизируется | веб‑портал Bolt Business | приватный API мобильного приложения |
| Вход | email + пароль (браузер) | телефон + код из СМС |
| Команда входа | `npm run login` | `npm run login:mobile` |
| Множитель спроса (surge) | обычно нет | да, приходит явно |
| Скорость запроса | секунды (браузер) | доли секунды (HTTP) |
| Надёжность | зависит от вёрстки портала | зависит от приватного контракта |

Мобильный источник быстрее и отдаёт `surge_multiplier`, которого нет даже в самом
приложении. Но контракт приватный: пути входа известны, а тела запросов публично не
описаны, поэтому вход может потребовать подгонки — при ошибке включите
`DEBUG_CAPTURE=1`, и полный ответ Bolt сохранится в `.debug/`.

> Bolt держит одну активную сессию на аккаунт: вход «новым устройством» может
> разлогинить приложение на вашем телефоне.

Если у вас уже есть токен из перехвата трафика приложения, вход по СМС не нужен —
положите его в `BOLT_ACCESS_TOKEN`.

## Как это работает

1. `npm run login` — один раз вручную входите в Bolt Business (email/пароль + код из
   письма/СМС). Сессия сохраняется в `.session/storageState.json`.
2. Сервер (`npm start`) поднимает веб‑интерфейс. При каждом запросе он:
   - открывает портал с сохранённой сессией (повторный логин не нужен);
   - вводит адреса «откуда/куда» через автоподсказки;
   - перехватывает JSON‑ответы бэкенда Bolt и/или читает DOM;
   - извлекает список тарифов: название, цена, время подачи, множитель спроса (surge).

Извлечение цен устойчивое: сначала парсятся сетевые JSON‑ответы
(`src/priceExtractor.js`), при неудаче — фолбэк на чтение DOM.

## Установка

Требуется **Node.js 20+** (Playwright ≥1.62 объявляет `engines.node: ">=20"`).

```bash
cd bolt-price-parser
npm install            # поставит зависимости и браузер Chromium для Playwright
cp .env.example .env   # заполните BOLT_EMAIL и BOLT_PASSWORD
```

Если `postinstall` не скачал браузер, выполните вручную:

```bash
npx playwright install chromium
# на Linux при нехватке системных библиотек:
npx playwright install-deps chromium
```

## Первый вход (сохранение сессии)

Выполняется один раз (и повторно, когда сессия протухнет):

```bash
npm run login
```

Команда **всегда** открывает видимое окно браузера (headed), даже если в `.env`
стоит `HEADLESS=true` — иначе нельзя ввести OTP/2FA. Значение `HEADLESS` влияет
только на сервер (`npm start`). Headless-login только при явном opt-in:

```bash
npm run login -- --headless
# или
LOGIN_HEADLESS=1 npm run login
```

Войдите в аккаунт и, если попросят, введите код подтверждения. Скрипт не угадывает
момент входа: когда на экране будет ваш кабинет, вернитесь в терминал и нажмите `Enter`.
Сессия сохранится, только если проверка подтвердит, что открыт кабинет, а не форма
входа (промежуточный OTP/consent сессию не перезапишет).

После сохранения скрипт выведет адрес вашего кабинета — скопируйте его в `.env` как
`BOLT_PORTAL_URL`. Это важно: корень `business.bolt.eu` отдаёт **публичную рекламную
страницу**, а не кабинет.

> На сервере без графики (headless‑окружение) вход в headed‑режиме невозможен. В этом случае
> выполните `npm run login` на своём компьютере и скопируйте файл
> `.session/storageState.json` на сервер.

## Первый вход через мобильное приложение (`PROVIDER=mobile`)

```bash
npm run login:mobile -- +37120000000
```

Номер можно и не указывать — тогда скрипт спросит его сам. Bolt пришлёт код в СМС,
после подтверждения токен сохранится в `.session/mobile.json`, и сервер подхватит его
автоматически: править `.env` не нужно.

> СМС приходит только на запрос с обычного домашнего интернета. При запросе из
> дата‑центра Bolt отвечает `code: 0, "OK"` с пустым `data`, но сообщение не
> отправляет — это анти‑фрод, а не ошибка программы.

Графический браузер для этого не нужен — подходит и сервер без экрана.

## Запуск

```bash
npm start
```

По умолчанию сервер слушает только `127.0.0.1` (см. `HOST`). Откройте
<http://localhost:4000>, введите адреса и нажмите «Узнать цены».

Опционально задайте `API_TOKEN` в `.env` — тогда `POST /api/prices` потребует
`Authorization: Bearer …`. Веб-UI подставляет токен сам. Также действует простой
per-IP rate limit (`RATE_LIMIT_MAX` / `RATE_LIMIT_WINDOW_MS`).

## API

- `GET /api/health` — статус (заданы ли доступы, есть ли сессия, нужен ли токен).
- `POST /api/prices` — тело `{ "pickup": "...", "destination": "..." }`.
  Если задан `API_TOKEN` — заголовок `Authorization: Bearer <токен>` (или `X-API-Token`).
  Ответ:

```json
{
  "pickup": "Rīga, Brīvības iela 1",
  "destination": "Rīga, Lidosta «Rīga»",
  "city": "Rīga",
  "currency": "€",
  "fetchedAt": "2026-08-09T17:00:00.000Z",
  "tariffs": [
    { "name": "Bolt", "price": "€12.50", "eta": "3 min", "surge": 1 },
    { "name": "XL", "price": "€18.90", "eta": "5 min", "surge": 1.2 }
  ],
  "source": "bolt-business-web"
}
```

## Настройки (.env)

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `PROVIDER` | источник цен: `auto`, `web` или `mobile` | `auto` |
| `BOLT_PHONE` | телефон аккаунта для `PROVIDER=mobile` | — |
| `BOLT_ACCESS_TOKEN` | готовый токен приложения (вместо входа по СМС) | пусто |
| `BOLT_APP_VERSION` | версия мобильного приложения в запросах | `CA.218.0` |
| `BOLT_EMAIL`, `BOLT_PASSWORD` | доступы Bolt Business | — |
| `BOLT_BASE_URL` | адрес портала | `https://business.bolt.eu` |
| `BOLT_PORTAL_URL` | точный адрес кабинета после входа (подскажет `npm run login`) | пусто |
| `BOLT_DEFAULT_CITY` / `BOLT_DEFAULT_COUNTRY` | город/страна | `Rīga` / `Latvia` |
| `HEADLESS` | фоновый браузер **для сервера** (`npm start`); на `npm run login` не влияет | `true` |
| `LOGIN_HEADLESS` | явный headless для `npm run login` (альтернатива флагу `--headless`) | выкл. |
| `GEO_LAT`, `GEO_LNG` | координаты по умолчанию | центр Риги |
| `HOST` | интерфейс прослушивания | `127.0.0.1` |
| `PORT` | порт сервера | `4000` |
| `API_TOKEN` | опциональный токен для `POST /api/prices` | пусто |
| `RATE_LIMIT_MAX` / `RATE_LIMIT_WINDOW_MS` | per-IP лимит на `/api/prices` | `20` / `60000` |
| `DEBUG_CAPTURE` | сохранять скриншот+JSON при запросе | `0` |

## Отладка

Если тарифы не находятся:

1. Установите `DEBUG_CAPTURE=1` в `.env` и повторите запрос.
2. Посмотрите скриншот и `*.json` в папке `.debug/` — там видно, что реально пришло со страницы.
3. При изменившейся вёрстке скорректируйте подсказки/селекторы в `src/boltBusiness.js`
   (`PICKUP_HINTS`, `DEST_HINTS`) или ключи в `src/priceExtractor.js`.

## Альтернатива: внутренний мобильный API

Более стабильно (и с явным `surge_multiplier`) цены отдаёт внутренний API
мобильного приложения (`user.live.boltsvc.net`), но он требует **токена**, который
можно получить только перехватом трафика приложения (MITM/HTTP Canary) и который не
привязан к email/паролю. Если сможете добыть такой токен — этот путь надёжнее; текущая
реализация использует доступный вам вход по логину/паролю.
